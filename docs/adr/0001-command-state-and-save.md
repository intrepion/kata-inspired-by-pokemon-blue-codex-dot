# ADR 1 — synchronous command state and versioned saves
Accepted. Use a pure TypeScript command reducer and seeded randomness; DOM rendering is an adapter. Alternatives included callback-driven battle animations and a framework store. A synchronous transition makes each action, enemy response and reward atomic and testable; it permits exact interrupted-battle saves without duplicated rewards. Animations never mutate gameplay. Store full validated v1 state after every command, including the PRNG seed. Reject structurally invalid saves, unknown versions and inconsistent creature IDs/collections. Saves remain local to this browser.
